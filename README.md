# Spring Boot Chat Backend

Real-time chat backend built with **Spring Boot**, **WebSocket (STOMP over SockJS)** and **MongoDB**.

It lets any frontend (for example an Angular client) connect, announce a new user, send messages, show a "user is typing" indicator and load the latest saved messages when joining the chat.

## What it is used for

- Broadcasting chat messages to every connected client in real time.
- Assigning a random color to each new user that joins.
- Notifying the rest of the users when someone is typing.
- Persisting messages in MongoDB and sending the most recent ones to a client when it connects.

## Tech stack

- Java 21
- Spring Boot 4 (WebSocket, Web MVC, Validation, Actuator)
- Spring Data MongoDB
- MongoDB 8
- Docker and Docker Compose
- JUnit 5 and Mockito

## Endpoints

### WebSocket connection

| Purpose | URL |
|---|---|
| STOMP endpoint (with SockJS fallback) | `/chat-websocket` |

Allowed origins are configured with `CHAT_ALLOWED_ORIGINS`.

### Messages the client sends

All destinations use the `/app` prefix.

| Destination | Payload | Description |
|---|---|---|
| `/app/message` | `MessageRequest` (JSON) | Sends a message or announces a new user. |
| `/app/writing` | username (plain text) | Tells the others that this user is typing. |
| `/app/history` | client id (plain text) | Requests the latest saved messages. |

### Topics the client subscribes to

| Topic | Payload | Description |
|---|---|---|
| `/chat/message` | `Message` (JSON) | Every message and new-user notification. |
| `/chat/writing` | text, e.g. `john has written...` | Typing notifications. |
| `/chat/history/{clientId}` | list of `Message` (JSON) | Latest messages, oldest first. Only the client that asked for it should subscribe, using its own id. |

The client id must match `[\w-]{1,64}` (letters, digits, `_` and `-`). Invalid requests are ignored.

### HTTP

| Method | URL | Description |
|---|---|---|
| `GET` | `/actuator/health` | Health check. |

## Data model

**`MessageRequest`** (what the client sends):

| Field | Type | Rules |
|---|---|---|
| `type` | `NEW_USER` or `MESSAGE` | Required |
| `username` | string | Required, not blank, max 30 characters |
| `text` | string | Max 500 characters. Empty messages are ignored |
| `color` | string | Max 20 characters |

**`Message`** (what the server sends and stores in the `messages` collection):

| Field | Type |
|---|---|
| `id` | string (generated by MongoDB) |
| `text` | string |
| `date` | number (epoch milliseconds, set by the server) |
| `username` | string |
| `type` | `NEW_USER` or `MESSAGE` |
| `color` | string |

For `NEW_USER` the server assigns a random color and does not save the message. For `MESSAGE` the server sets the id and the date and saves it.

## Usage example

Using `@stomp/stompjs` and `sockjs-client`:

```javascript
import { Client } from '@stomp/stompjs';
import SockJS from 'sockjs-client';

const clientId = 'client-123';

const client = new Client({
  webSocketFactory: () => new SockJS('http://localhost:8080/chat-websocket'),
  onConnect: () => {
    client.subscribe('/chat/message', (frame) => console.log(JSON.parse(frame.body)));
    client.subscribe('/chat/writing', (frame) => console.log(frame.body));
    client.subscribe(`/chat/history/${clientId}`, (frame) => console.log(JSON.parse(frame.body)));

    client.publish({ destination: '/app/history', body: clientId });
    client.publish({
      destination: '/app/message',
      body: JSON.stringify({ type: 'NEW_USER', username: 'john' }),
    });
    client.publish({
      destination: '/app/message',
      body: JSON.stringify({ type: 'MESSAGE', username: 'john', text: 'Hello!', color: 'blue' }),
    });
  },
});

client.activate();
```

## Configuration

| Environment variable | Default | Description |
|---|---|---|
| `PORT` | `8080` | Server port |
| `MONGODB_URI` | `mongodb://localhost:27017/springboot_chat` | MongoDB connection string |
| `CHAT_ALLOWED_ORIGINS` | `http://localhost:4200` | Allowed origins for WebSocket connections |
| `CHAT_HISTORY_SIZE` | `10` | Number of messages sent as history |

## Running the project

### With Docker Compose

```bash
cp .env.example .env
# edit .env and change MONGO_PASSWORD
docker compose up --build
```

The API is available at `http://localhost:8080` and MongoDB runs in its own container with a persistent volume.

### Locally

Requirements: Java 21 and a MongoDB instance running on `localhost:27017`.

```bash
./mvnw spring-boot:run
```

### Tests

```bash
./mvnw test
```
